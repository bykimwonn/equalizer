# Troubleshooting

## Engine won't start / “native module not loaded”

**Symptom:** Devices screen shows `native module not loaded: …` and engine
status is `error`.

Causes & fixes:

1. **Not built yet** — run `npm run build:native` (Windows, VS Build Tools +
   Windows SDK). Expect `native/wasapi/build/Release/bt_wasapi.node`.
2. **Wrong platform** — the WASAPI backend is Windows-only. Use the
   Simulation backend (Settings → Audio Engine → Backend) for development.
3. **Electron ABI mismatch** — rebuild after changing Electron versions:
   `npm run build:native` (node-gyp compiles against the local Node/Electron
   headers; if `electron-rebuild` is used in your environment, run it too).

## Start fails with “process-loopback activation failed”

Your Windows build predates 2004 (19041) or the activation API refused. The
engine falls back to classic loopback and reports it. With classic loopback,
render to a **different** device than the one you capture (e.g. a virtual
cable), or you will hear feedback/doubling.

## I hear the audio twice / echo

You are rendering into the same endpoint that classic loopback captures.
Either switch to Enhanced Path (`process-loopback`), or render to a virtual
cable and make the cable the default playback device.

## No sound after enabling processing

1. Check the master toggle (Overview) isn't showing `Bypassed` — bypass is
   bit-exact, so if bypassed you hear the original; if enabled and silent:
2. Output device selection (top bar / Devices) — set to `Default output`.
3. Limiter ceiling extremely low? Raise “Limiter ceiling” (Stereo & Output).
4. Look at “NaN guard trips” and “Last error” in Devices → Engine Health.

## Distortion / pumping

- Reduce Bass `Harmonics` (0 = off) and `gainDb`; enable `Bass protection`.
- Compressor ratio > 8 with low threshold will pump — lower ratio or disable.
- Check “Limiter events”: sustained clamps mean input is too hot — lower
  `Output` gain (the clip guard also steps it down automatically).

## AI panel says “not configured”

Add an API key in Settings → AI Providers (Groq and/or Gemini), click
**Test connection**. The app works fully without keys — this message only
affects AI recommendations.

## “throttled: min interval …”

Expected. Raise request frequency in Settings → AI Providers (or press
“Request recommendation” which forces a call).

## AI recommendations are rejected/clamped

The validator clamps out-of-range numbers (warnings listed in the AI panel)
and rejects structurally invalid proposals. This is by design — AI output can
never destabilize the DSP. Check the controller log in Personalization for the
exact reason.

## Tray icon missing

The tray uses `build/icon.png` (generated by `node scripts/gen-icon.js`).
Regenerate if deleted. Tray failure never blocks the app.

## APO won't load (system-wide mode)

`audiodg.exe` rejects unsigned APOs. Options (see docs/INSTALL-WINDOWS.md §4):
sign the DLL (release path), enable test signing, or the documented
`DisableProtectedAudioDG` override. Registration is reversible via
`register-apo.ps1 -Unregister`.

## Config corruption / reset

Delete `%APPDATA%\BT AI Equalizer\config\` while the app is closed. Defaults
recreate on next start. API keys live in the OS credential store — re-enter
them in Settings if needed. Personalization can be reset in-app
(Personalization → Reset personalization).

## Reporting a bug

Attach: Settings → Diagnostics values (engine blocks, NaN trips, clip events,
controller actions, backend labels), Windows version, audio device list.
No logs are written to disk by default — nothing to clean up, nothing leaks.
